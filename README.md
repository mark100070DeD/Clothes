# Puma UA — бот скидок на кроссовки

Обходит разделы «скидки → обувь» на ua.puma.com, отбирает кроссовки и кеды со сниженной
ценой и присылает в Telegram фото, цену, старую цену, процент скидки, цвет и размеры
в наличии. Один товар уходит один раз; повторно — только если цена упала ещё ниже.

Скидки ищет Cloudflare Worker: он просыпается раз в минуту, так что новая уценка
доходит за несколько минут, а не за час. GitHub остался на суточной сверке и на
запасной рассылке. Компьютер не нужен. Бот: @ClothessSalee_bot.

## Что где лежит

```

requirements.txt    зависимости Python

  config.py           настройки: токен, адреса сайта, лимиты
  models.py           что такое «товар» (Item)
  scraper.py          ходит на сайт Пумы и разбирает страницы
                      (если Пума поменяет вёрстку — чинить здесь)
  storage.py          база: что бот уже показывал
  messages.py         тексты сообщений и вид карточки
  sender.py           отправка в Telegram, ответ на /start
  checker.py          главная логика: что новое, что подешевело
  subs_sync.py        забирает подписчиков из Worker в базу
  klevu.py            каталог через поисковый индекс Пумы (быстро и полно)
  audit.py            суточная сверка индекса с живым сайтом + сторож Worker'а
  app.py              режимы запуска

data/puma.db        память бота (какие товары уже отправлены)
tests/              автотесты, чтобы правка не ломала старое
tools/              служебные питон-скрипты
scripts/            двойным кликом: запуск, проверки, заливка

  puma.yml            суточная сверка + запасная рассылка

                      свой README внутри — там же инструкция по починке
```

Карта проекта с картинкой «что кого вызывает» лежит в шапке `bot.py`, а в начале
каждого файла `puma/` написано, за что он отвечает и что в нём править.

## Почему кнопки отвечают мгновенно

Обработчики команд **не парсят сайт**. Раньше `/start` запускал обход прямо в
обработчике, и человек ждал полминуты. Теперь так:

```
фоновый обход (раз в прогон)          обработчик команды (мгновенно)
  ходит на сайт                          НЕ ходит в сеть
  собирает карточки целиком              читает готовое из базы
  кладёт их в таблицу deals   ------>    отправляет 5 карточек
```

Готовые карточки — с названием, ценами, цветом и размерами — складывает
`checker.refresh_deals` в таблицу `deals`. Он же выбрасывает устаревшие: если
товар ушёл с распродажи или цена изменилась, карточка пересобирается.

`/who` так же: быстрый `COUNT` и выборка последних пользователей из базы, без
единого сетевого вызова.

Пока витрина пуста (например, сразу после чистой базы) `/start` честно отвечает,
что скидки ещё не собраны — и они появятся после ближайшего обхода.

## Как это работает

Основную работу делает Cloudflare Worker. Крон будит его раз в минуту:

```
минуты 0,1 каждой пятиминутки → 1 живая страница списка Пумы   (свежесть)
минуты 2,3,4                  → 2 страницы каталога из индекса (полнота)
                    ↓
      новый артикул или цена ниже запомненной
                    ↓
      страница товара → ЦЕНА, размеры, цвет  ← истина берётся здесь
                    ↓
      карточка в Telegram
```

**Два источника, и это важно.** Поисковый индекс Пумы (Klevu) отдаёт весь каталог
из 5183 товаров за 6 запросов и 1.26 МБ — покрытие распродажи полное, проверено
сверкой 591 из 591. Но индекс отстаёт на свежих уценках: замер 25.09.2026 показал
расхождение на 2 товарах из 89, и **оба раза живой сайт был дешевле**. Поэтому
индекс даёт полноту, живые страницы — скорость, а цена в карточке **всегда**
берётся со страницы товара и никогда из индекса. Прислать неверную цену
невозможно по устройству.

**GitHub теперь делает мало и редко** — раз в сутки, `python bot.py --audit`:

- сверяет цены индекса с живым сайтом и кричит, если индекс застрял;
- следит за самим Worker'ом: тот про свою смерть не напишет, он мёртв. Если
  Worker молчит дольше `STALE_HOURS`, сверка кричит и **включает запасную
  рассылку** — старый полный обход `--once`. Задержка вырастает до суток, но
  скидки продолжают приходить.

Суточное расписание выбрано намеренно: частые кроны GitHub душит (прежний `*/5`
не срабатывал ни разу), а суточный тянет. Дёргать его снаружи не надо — и токена
для этого не надо тоже.

**Нагрузка на сайт Пумы упала.** Было ~1300 запросов в сутки независимо от того,
есть скидки или нет. Стало ~600, и большая часть — редкое окно живых страниц;
опрос переехал на поисковый индекс, который Пума и держит для нагрузки.

**Режимы запуска:**

- `--audit` — суточная сверка (это и крутится на GitHub);
- `--once` — полный обход и рассылка, запасной путь;
- `--answer` — забрать команды из чата; сейчас бесполезен, при активном webhook
  Telegram отдаёт 409;
- без флага — бот живёт постоянно, для запуска на своём компе.

## Кому приходят скидки

Подписка открытая. Любой, кто написал боту `/start`, попадает в таблицу `subs`
в `data/puma.db` и дальше получает карточки сам. Плюс к подписчикам всегда
владелец из настройки `CHAT_ID` — его из рассылки не выкинуть.

**Путь нового подписчика идёт через Cloudflare.** На `/start` отвечает Worker,
поэтому человек попадает сначала в его хранилище KV, а уже часовой обход
забирает список (`GET /subs`, пароль `SUBS_TOKEN`) и переносит в базу — это
делает `puma/subs_sync.py`. Пока включён webhook, `getUpdates` отдаёт 409, так
что сам Python новых подписчиков не увидит. Если `WORKER_URL` или `SUBS_TOKEN`
не заданы, шаг молча пропускается: старые подписчики рассылку получают, новые не
появляются.

Кто заблокировал бота, вылетает из подписки автоматически: мёртвый чат незачем
держать и незачем тормозить на нём каждую рассылку.

**Как посмотреть, кто подписан.** Два способа:

- написать боту `/who` — он мгновенно ответит: сколько всего пользователей и кто
  пришёл последним (имя, `@username`, id, дата входа). Отвечает **только админу**
  (`ADMIN_ID`, по умолчанию владелец); остальным — «У вас нет доступа к этой команде»;
- двойной клик `scripts/subscribers.bat` — сам подтянет базу с сервера и покажет
  список в окне.

Имя берётся из `@username`, иначе из имени с фамилией. У тех, кто подписался до
того, как бот начал запоминать имена, вместо имени будет только номер чата —
имя появится при следующем `/start`.

Важно: отметка «товар уже отправлен» общая для всех, а не у каждого своя. Поэтому
подписавшийся позже прошлые скидки не получит, только будущие — ему вместо этого
сразу приходит витрина. И бот не годится на роль публичного: **ссылку на него
стоит давать только тем, кому правда нужны эти скидки.**

## Скрипты (папка scripts)

| Файл | Что делает |
|---|---|
| `edit-env.bat` | создаёт и открывает `.env` для токена |
| `run-local.bat` | запускает бота на компе, лог в `logs/bot_log.txt` |
| `run-once.bat` | один проход, как на GitHub |
| `check-site.bat` | проверка без Telegram: доступен ли сайт, что видит парсер |
| `subscribers.bat` | кто подписан на бота и сколько их |
| `push-seen.bat` | разово: перенести память бота из базы в хранилище Worker |
| `fill-showcase.bat` | наполнить витрину для `/start`, без Telegram |
| `run-tests.bat` | прогон автотестов |
| `publish.bat` | коммит и заливка на GitHub (с `git pull` перед пушем) |

## Настройки (.env для запуска на компе, Secrets для GitHub)

| Переменная | Что делает |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `CHAT_ID` | владелец: ему шлём всегда, даже если он не жал `/start` |
| `INTERVAL_MIN` | период проверки в минутах при постоянной работе, по умолчанию 60 |
| `MIN_DISCOUNT` | слать только от N% скидки, по умолчанию 0 (всё подряд) |
| `START_ITEMS` | сколько карточек показать по `/start`, по умолчанию 5 |
| `ADMIN_ID` | кому отвечает `/who`; по умолчанию владелец из `CHAT_ID` |
| `USERS_SHOWN` | сколько последних пользователей в `/who`, по умолчанию 10 |
| `DEALS_KEEP` | сколько готовых карточек держать в витрине, по умолчанию 50 |
| `WORKER_URL` | адрес Worker'а: откуда забирать подписчиков и его память |
| `SUBS_TOKEN` | пароль к `/subs` и `/state` Worker'а |
| `AUDIT_PAGES` | страниц выборки для суточной сверки, по умолчанию 2 |
| `AUDIT_MISMATCH_PCT` | с какого расхождения цен кричать, по умолчанию 10% |
| `STALE_HOURS` | через сколько часов молчания Worker'а включать запасной путь, по умолчанию 6 |

На GitHub секреты лежат в Settings → Secrets and variables → Actions: `BOT_TOKEN`,
`CHAT_ID`, `WORKER_URL`, `SUBS_TOKEN` и необязательный `HC_URL` — адрес внешнего
монитора (healthchecks.io и подобные). `HC_URL` закрывает случай «умерло всё
сразу»: изнутри такое не поймать, некому крикнуть. Нет секрета — шаг молча
пропускается.

**Что делать, когда сломалось** — таблица «симптом → команда» в
[worker/README.md](worker/README.md).

## Как понять, какая это скидка

Подпись в карточке: «Новая скидка» — бот этого товара раньше не видел;
«Цена упала (было X ₴)» — цена стала ниже запомненной; «Сейчас на распродаже» —
витрина по `/start`, не новость.
