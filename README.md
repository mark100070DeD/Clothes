# Puma UA — бот скидок на кроссовки

Раз в час обходит разделы «скидки → обувь» на ua.puma.com, отбирает кроссовки и кеды
со сниженной ценой и присылает в Telegram фото, цену, старую цену, процент скидки,
цвет и размеры в наличии. Один товар уходит один раз; повторно — только если цена
упала ещё ниже.

## Запуск на компьютере

1. Заведи бота в @BotFather, скопируй токен.
2. Запусти `run.bat` — он создаст `.env` и откроет его в блокноте.
3. Вставь токен после `BOT_TOKEN=`, сохрани, закрой блокнот.
4. Запусти `run.bat` ещё раз. Напиши боту `/start` — он пришлёт твой chat id.
5. Впиши id после `CHAT_ID=` в `.env`, сохрани и запусти `run.bat` снова.

Первый запуск молча запоминает всё, что уже на распродаже, и шлёт только новое.
Команда `/now` в чате запускает проверку вручную.

Файл `check.bat` — проверка без телеграма: доступен ли сайт и что находит парсер.

## Работа без компьютера (GitHub Actions)

Бот умеет ходить одним проходом: `python bot.py --once`. На этом построен
`.github/workflows/puma.yml` — он запускается на серверах GitHub каждый час,
бесплатно, компьютер при этом не нужен.

1. Создай **приватный** репозиторий на GitHub и залей туда эту папку.
   Файл `.env` не попадёт в репозиторий, он в `.gitignore` — это правильно,
   токен в репозитории хранить нельзя.
2. В репозитории: Settings → Secrets and variables → Actions → New repository secret.
   Добавь два секрета: `BOT_TOKEN` и `CHAT_ID` с теми же значениями, что в `.env`.
3. Вкладка Actions → выбери «puma sale check» → Run workflow. Это первый запуск,
   он запомнит текущую распродажу и создаст `puma.db`.

Дальше он идёт по расписанию сам. Состояние (какие товары уже отправлены) хранится
в `puma.db`, который workflow коммитит обратно в репозиторий после каждого прохода —
поэтому запуски помнят друг друга.

Что нужно знать про этот способ:

- Расписание GitHub не точное, запуск может опоздать на 5–20 минут. Для скидок это неважно.
- Бесплатные минуты Actions на приватном репозитории ограничены (2000/мес). Один проход
  занимает около минуты, за месяц выходит ~750 — влезает с запасом.
- В этом режиме команды `/start` и `/now` не работают: бот не слушает чат, а только
  присылает сообщения. Chat id возьми при запуске на компьютере, один раз.
- Если репозиторий не трогать 60 дней, GitHub отключает расписание. Наш workflow
  коммитит состояние каждый час, так что репозиторий всё время активен.

Альтернатива, если захочешь надёжнее и без этих оговорок — VPS за пару долларов в месяц,
там просто `python bot.py` под systemd. Но для одной проверки в час это лишнее.

## Настройки в .env

| Переменная | Что делает |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `CHAT_ID` | куда слать (узнаётся командой `/start`) |
| `INTERVAL_MIN` | период проверки в минутах, по умолчанию 60 |
| `MIN_DISCOUNT` | слать только от N% скидки, по умолчанию 0 (всё подряд) |
